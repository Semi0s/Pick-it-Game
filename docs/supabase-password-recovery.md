# Supabase Password Recovery

PICK-IT uses `@supabase/ssr` and supports both auth callback shapes:

- `code=...` through `exchangeCodeForSession`
- `token_hash=...&type=recovery` through `verifyOtp`

For password recovery emails that can be generated by an admin/server process, prefer the `token_hash` link. A PKCE `code` link requires the code verifier that was saved in the same browser/device that initiated the reset. Admin-generated recovery emails do not have that verifier in the player's browser, so they can fail with:

`PKCE code verifier not found in storage`

## Recommended Supabase Recovery Email Link

In the Supabase Auth password recovery email template, use the token hash form:

```html
<a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/reset-password">
  Reset your password
</a>
```

If language-specific redirects are needed, append `&lang=<language>` from the sending path when practical. The app will fall back safely if `lang` is omitted.

## App Behavior

`/auth/confirm` verifies `token_hash` links server-side, sets the Supabase session cookies, then redirects to `/reset-password`.

If a PKCE `code` link is opened without its verifier, the reset page now shows a friendly localized message asking the user to request a fresh reset link from the current browser.
